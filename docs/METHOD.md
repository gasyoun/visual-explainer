# Метод: как посчитан «налог на токены»

_Created: 24-10-2026 · Author: Dr. Mārcis Gasūns · Model: DeepSeek Flash (`deepseek-flash`)_

## Вопрос

Один и тот же смысл на разных языках стоит разного числа токенов. Насколько
разного — и зависит ли это от токенизатора?

## Корпус

**FLORES-200 devtest** — стандартный параллельный корпус для оценки
многоязычных моделей: 1 012 предложений, выровненных по языкам.

- Языки: `eng_Latn` (EN), `rus_Cyrl` (RU), `hin_Deva` (HI), `san_Deva` (SA).
- Лицензия: CC-BY-SA 4.0.
- Источник: <https://github.com/facebookresearch/flores>.
- Файлы: `flores200_dataset/devtest/*.devtest` из
  `https://dl.fbaipublicfiles.com/nllb/flores200_dataset.tar.gz`.

Почему FLORES: это не мои переводы и не подборка под удобный ответ. Один и
тот же набор предложений, профессиональный перевод, открытая лицензия.

| DeepSeek-V3 | `deepseek-ai/DeepSeek-V3` | `e815299b0bcbac849fa540c768ef21845365c9eb` |

лицензии. Пять открытых достаточно, чтобы показать разброс.

## Метрики

Для каждого токенизатора и языка:

- `tokens_total` — сумма токенов по 1 012 предложениям.
- `ratio_total` — `tokens_total(lang) / tokens_total(EN)`.
- `ratio_median` — медиана по предложениям: `tokens(lang, i) / tokens(EN, i)`.
- `ratio_p10`, `ratio_p90` — разброс по предложениям.
- `tokens_per_100_chars` — длина-нормализованная плотность.
- `tokens_per_word` — альтернативная нормализация.

Почему не только `ratio_total`: переводы разной длины. Русский перевод
предложения обычно длиннее английского, поэтому `ratio_total` включает и
плотность, и длину. `tokens_per_100_chars` фиксирует длину, а медиана
показывает типичное предложение.

## Результат

| Токенизатор | EN, токенов | RU / EN | HI / EN | SA / EN |
|---|---:|---:|---:|---:|
| GPT-4o (o200k) | 26 873 | 1.42× | 1.57× | 2.08× |
| GPT-4 (cl100k) | 27 182 | 2.46× | 4.76× | 4.94× |
| Qwen2.5 | 27 621 | 1.75× | 4.42× | 4.51× |
| DeepSeek-V3 | 27 041 | 1.58× | 2.79× | 2.86× |
| Mistral-7B | 29 997 | 1.85× | 4.55× | 4.60× |

Три вывода:

1. Новый OpenAI-токенизатор сократил русский до 1.42×, но санскрит остался
   2.08×: прогресс неравномерен по письменностям.
2. DeepSeek — самый дружелюбный к деванагари из пяти (2.79–2.86×); Qwen —
   самый дорогой (4.42–4.51×), несмотря на мультиязычное позиционирование.
3. Хинди и санскрит ведут себя почти одинаково: это цена деванагари, а не
   «сложности санскрита».

## Кейсы (иллюстративные)

`case_studies.json` содержит два ручных параллельных текста: короткий
чат-промпт и стих Бхагавадгиты 2.47. Они показывают эффект регистра, но **не
входят** в основной аудит: переводы не выровнены по длине, а санскритский
стих — не тот же регистр, что FLORES.

## Оговорки

- **Токенизатор — не модель.** Это стоимость токенов, не качество ответов.
  Дешёвый токенизатор может быть хуже на вашей задаче.
- **FLORES — переводы.** Это не параллельные тексты одной длины; смотрите
  медиану и токены на 100 символов, а не только суммарное отношение.
- **Санскрит во FLORES — перевод**, а не оригинал. Для оригинального
  санскрита плотность может отличаться.
- **Только входные токены.** Кэш, выход, скидки и биллинговые округления не
  учтены; калькулятор — нижняя граница.
- **Нет API-счётчиков Claude/Gemini.** Их токенизаторы не опубликованы в
  открытом виде; добавление потребует ключей и отдельного прогона.

## Воспроизведение

```bash
uv run --with tiktoken --with transformers --with huggingface_hub \
  python tools/measure_tokens.py
```

Скрипт скачивает FLORES-200 в `.cache/`, считает все метрики и пишет:

- `examples/token-tax/data/flores_results.json` (ревизии + метрики),
- `examples/token-tax/data/flores_results.csv`,
- `examples/token-tax/data/case_studies.json`.

Полоски токенов для страницы — отдельно:

```bash
uv run --with tiktoken python tools/make_token_strips.py
```
